# 5E观赛组件输入排查（2026-11-12）

## 实际定位

测试页面为用户提供的1883358196直播间。组件是oss.5eplay.com/nesting_file/536.html的跨域iframe；“参赛队伍/赛程/数据”为DOM div按钮，隐藏canvas并非这些按钮的输入实现。DOM点击能改变内容，说明初始化并未整体失败。

未发现inert、pointer-events禁用或阻挡该区域的透明层；隔离会话未启用DragOverlay，仍可复现。自动适配及响应式下的Electron sendInputEvent均可能只命中iframe外壳，不能据此判定系统鼠标结果。因此随后采用真实系统鼠标和用户对照。

## 因果对照

- 用户确认原软件响应式可交互，自动适配不可交互。
- iframe实际宽14400px，但缩为1920px并保留原自动缩放后，用户确认两种宽度均不能交互，排除宽度单变量根因。
- 直接换成CDP设备模拟仍未得到可交付的成功结果，没有引入产品。
- 同一隔离页面保留逻辑视口及图像大小，F8为原enableDeviceEmulation.scale路径，F9为setZoomMode('isolated')加原生缩放。用户确认F9可以、F8不可以。

故已定位当前设备图像模拟缩放与该跨进程iframe输入命中的兼容问题，并证明独立原生缩放可绕开该故障路径；未断言某个未经验证的Chromium缺陷编号或适用于所有iframe的上游根因。

## 针对性修复

仅在live.bilibili.com页面实际加载5E nesting_file嵌入文档后，对auto模式及25%–500%比例启用独立原生页面缩放。仍使用原fit矩形、相同网页实例和页面配置；其余网站、响应式、手动裁剪、拖拽覆盖层与音频保持原入口。记录可见bounds，后加载组件时刷新布局；隐藏页面不会被组件加载事件重新显示，关闭时清理映射。

独立缩放防止同域页面比例相互影响。主进程API实际将小于25%的值夹到25%；渲染端webFrame虽可报告0.1，实际布局仍可能按25%计算（192px视图出现768px逻辑宽度），因此未使用该伪成功方案。低于25%仍使用原设备模拟，保留原逻辑视口但输入兼容问题未解决。手动比例亦未覆盖。原生路径逻辑视口受DIP舍入影响可有1–2px差异。

## 验证

实际网站的F8/F9真实鼠标A/B由用户确认。新增scripts/interaction-smoke.mjs检查25%边界、同域窗口隔离、10%回退、响应式切换、恢复及JS状态保留。合成输入不作为跨进程iframe实际可点击的独立证据。结果和本轮回归汇总见[验证记录](../VALIDATION.md)。没有更改sandbox、contextIsolation、站点权限或跨域隔离，没有将诊断网址/原始错误加入操作日志。
