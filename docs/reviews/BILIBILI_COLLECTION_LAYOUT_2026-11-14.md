# Bilibili大合集放大/恢复排版延迟

交付版本：V0.2.1.5。历史观测及被否决实验见[暂停检查点](RESIZE_DELAY_CHECKPOINT_2026-11-14.md)。

## 原因与修复范围

主窗口放大/恢复会按既定规则切换逻辑视口。问题视频含961条合集，右侧列表和播放器选集菜单共保留大量屏外节点；视口变化时Chromium仍为这些节点进行昂贵排版。原生尺寸/视口指令通常在约1–12ms内发出，延迟主要发生在网页排版阶段，没有找到此路径的1000ms等待。隔离移除列表的因果实验明显降低排版耗时，但删除方案未进入产品。

没有完成历史版本的同条件二分，不能将现象归因于某次近期提交。普通视频和较小合集不能代表大合集性能。

`electron/bilibili-layout.ts`仅在`www.bilibili.com/video/`顶层页面安装两条兼容CSS规则，使用Chromium原生`content-visibility:auto`延后屏外条目排版，配合31px/30px的intrinsic占位。占位不强制实际行高，显示区域内仍使用网站原来的内容、样式和事件。

`electron/media-preload.ts`在DOMContentLoaded安装规则。不删除列表、拦截网站事件或添加延时，不隐藏整个网页；BrowserManager、分屏、逻辑视口、Page Zoom、交换、焦点与音频运行代码均不变。

## 测量方法与结果

测试使用隔离临时配置，默认浏览器总静音。每组20次交替切换，即10轮完整放大/恢复。页面每20ms采样视口及播放器尺寸；记录主界面容器、setBounds、设备模拟、Page Zoom、页面resize及性能指标。数字时序不包含URL、标题或用户输入，生成文件被Git忽略。

同一大合集、四宫格、普通1080p/放大1440p、Page Zoom 100%，两组均启用相同合成帧抓取。基线仅在诊断实例中禁用兼容样式：

| 指标 | 基线 | V0.2.1.5兼容优化 |
| --- | --- | --- |
| 播放器尺寸响应 | 462–536ms | 83–146ms |
| 视口标记首次进入合成帧 | 508–591ms | 99–175ms |
| 20次累计LayoutDuration | 6.346秒 | 0.928秒 |
| 20次累计TaskDuration | 10.959秒 | 3.696秒 |

合成帧指标是在诊断网页左上角放置仅用于测试的媒体查询颜色标记，记录新颜色首次出现在Chromium输出帧中的时间；不是API返回时间，**也不是Windows最终显示或整幅视频完成更新的测量**。抓帧有额外开销，不直接与未抓帧轮次作严格前后比较。

最终未抓帧大合集回归：尺寸响应88–156ms，20次累计LayoutDuration 0.956秒；页面实例/JS标记保留、主框架导航0，视频开始及结束均播放、时间前进，浏览器始终静音。保留961条右侧条目及969条播放器选集条目。

## 交互与工程验证

- 大合集兼容开/关的全列表行高数组、条目数量、滚动高度相同；右侧滚动高度33631px，末端行高31px。
- 末条正是当前选集（索引960）；点击它不导航是正常行为。诊断工具后来排除当前项，使用原生视图坐标点击索引959，实际导航成功。早期仅比较原始传入URL或点击末条的结果不能作为选集成功证据，以`resize-resume-final-list-diagnostic.json`为准。
- 56项单测、类型检查、生产构建及格式检查通过。站点/路径/顶层限制新增5个测试。
- 六种交换案例实际WebContents焦点及实例保留通过；网页缩放/提示/交换/Canvas与Iframe交互专项通过；拖拽覆盖层隔离网页交互且保持播放通过。
- 旧缩放专项曾在提示框就绪前读取导致失败，增加测试侧焦点等待及有界就绪轮询后通过；未修改产品缩放逻辑。旧拖拽夹具增加总音量0，保留播放及交换断言。
- 原启动位置`release/win-unpacked/MultiViewBrowser.exe`已更新。Windows文件/产品版本均0.2.1.5，产品名MultiView Browser；包内main及相关preload哈希与验证构建一致。

## 局限与维护

这是特定网站模板的排版兼容优化，未保证所有视频、网站、未来DOM模板或多P展开形式完全一致。不同分辨率/布局有覆盖，未穷尽真实Windows多屏DPI。CSS intrinsic值依赖当前紧凑列表模板，后续网站改变行高/结构需要复核；不能通过强制高度或删除条目维持性能。

保留测试入口`node scripts/resize-transition-smoke.mjs`。`MVB_RESIZE_URL`、`MVB_RESIZE_CASE`、`MVB_LOGICAL_WIDTH`、`MVB_PAGE_ZOOM`和`MVB_LAYOUT_INDEX`选择场景；`MVB_DISABLE_COMPAT=1`仅在测试中移除兼容规则。`MVB_CAPTURE=1`的颜色标记度量仅适用于默认1080p/100%场景。`MVB_LIST_CHECK=1`比较滚动几何并点击非当前选集，属于独立的切换后导航阶段，不与切换期间的零导航断言混淆。
