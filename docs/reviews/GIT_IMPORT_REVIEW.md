# Git 导入前复查（2026-11-02）

本轮检查应用源码、主进程与preload、原生浮窗、构建与诊断脚本、测试、配置和既有审计记录。仅增加仓库管理、敏感信息扫描工具和本报告；保留全部现有代码。软件仍为V0.1.1.3，不因审计和Git导入增加行为版本。

## 结论

存在待修复的冲突风险，不能宣称代码没有缺陷。TypeScript的noUnusedLocals/noUnusedParameters检查、格式检查、31项测试通过，但这些检查不证明跨进程时序正确。

本轮重跑两个本地审计探针，确认以下四项仍存在：

1. **P1：旧快照覆盖新状态。** `src/App.tsx` 延迟保存整份Config，`electron/main.ts` 中原生音量、缩放及拖拽同时直接保存配置。runtime探针中100→浮窗25→旧快照保存100；建议统一主进程状态并引入修订号或字段补丁。
2. **P1：播放器来源交接不完整。** `electron/media-preload.ts` 只在旧来源断开或新媒体面积更大时交接；旧播放器暂停但留在DOM，同尺寸新播放器无法接管。media探针确认旧播放器.25、新播放器.75，后者音量变化没有反向同步。
3. **P2：站点音量同步解除静音。** `electron/main.ts` 的updatePageVolume共用于网页同步与用户音量操作，value>0无条件设unmuted。runtime探针确认静音子窗口被网页volumechange解除静音；需区分同步与用户解除静音意图。
4. **P2：原生网页焦点与UI选中槽位分离。** BrowserManager记录focus但未通知外层selected；runtime探针中第二网页已获焦点，UI仍选中主窗口。收藏相关操作可能选错目标。

其余静态风险沿用 [此前详细报告](REVIEW_2026-11-02.md)：收藏拖入已加载网页内容区缺少原生覆盖层路径；退出前异步最终保存没有握手；VolumePopup缺少屏幕边界约束（ScalePopup已有约束）；导入缺少分组和收藏ID的一致性校验。本轮未将这些静态风险说成新的稳定运行复现。

## 废弃、重复和无用代码判断

- 原先全屏遮罩的缩放设置面板及empty-title样式已经移除，未发现这些旧入口残留。
- `effectiveVolume`仅在测试中引用，生产增益实际位于media-preload。这是可精简的测试辅助API，并非当前音频链路的执行实现；本轮保留，避免以删除测试掩盖问题。
- BrowserManager.publish中的back/forward字段没有UI消费者，是可移除的多余IPC元数据。
- VolumePopup与ScalePopup重复了加载取消、hover计时和来源校验，可考虑抽取公共生命周期；二者的输入和状态逻辑不同，直接合并会引入风险。
- main与BrowserManager各自处理F11/Escape，分别服务外层界面与原生网页，属于必要的不同焦点入口，不能删掉其中一个。
- media-preload的audio-status/audio-probe及sources集合被直播诊断/音频验收使用；review-*、rooms-*、smoke脚本具有入口，不是遗留死代码。诊断结果和截图与源码区分：前者保留在本地但不提交，后者保留进Git。
- 操作日志仍通过固定白名单过滤，不将诊断消息、网址、标题或原始错误写入用户操作日志。
