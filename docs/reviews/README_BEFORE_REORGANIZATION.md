# MultiViewBrowser

窗口拖拽现使用独立原生透明交互层：拖动按钮开始换位后，底层网页持续播放与渲染，但鼠标点击、滚轮和拖放由交互层接收，不进入视频、聊天框或 iframe。交互层只负责目标高亮和槽位交换；放下、取消或移动主窗口后隐藏并恢复网页操作。此方案替代旧的网页内部拖放监听。

直播间音量修复：音量控制现在递归查找同源 iframe 内的媒体元素，并监听内嵌播放器加载、重建和 volumechange。此前只扫描顶层文档，导致35号等直播间真正的视频未受页面音量和总增益控制，而整个 webContents 的静音仍然有效。跨域文档仍保持隔离。

直播首页音量稳定性更新：页面 DOM 重绘不再持续抢写播放器音量；视频元素临时移除后重新挂载会复用并重连原音频链路，避免重复创建媒体源失败。更新后请关闭旧程序再启动。可用 node scripts/bilibili-smoke.mjs 对实际直播首页执行音量专项验证（需要访问 Bilibili），结果写入 bilibili-app-smoke-results.json。

主窗口移出规则：即使此前手动解除过静音，只要换位后离开主窗口，就恢复自动静音；原音量百分比保留。进入主窗口仍按有声规则处理，无关窗口的手动音频选择保持不变。

启动时默认最大化，保留窗口标题栏及系统任务栏。F11 仍可手动切换真正的全屏，Esc 退出全屏。主窗口放大功能仅调整内部网页分屏。

音量同步更新：子窗口音量与 HTML 播放器音量使用同一个绝对百分比，不再在播放器原音量上叠乘。网页原来75%时，子窗口调25%后播放器也是25%，不是19%。网页侧调整会同步回应用，并吸附至最近的五档值；总音量通过独立 Web Audio Gain 调整，不再改写播放器显示值。无法安全接入 Gain 的跨域、DRM 或已有音频图媒体，可能无法应用总音量增益/衰减；原生总静音保持有效。不支持标准 HTMLMediaElement 音量事件的自定义播放器 UI 仍可能需要站点适配。

Windows 多网页分屏浏览器，基于 Electron WebContentsView、TypeScript、React 和 Vite。网页为真实 Chromium 实例，支持正常浏览、登录、输入与网页媒体。

## 快速启动

双击项目根目录的 MultiViewBrowser.lnk 或 Start-MultiViewBrowser.cmd。成品路径为 release/win-unpacked/MultiViewBrowser.exe，必须保留整个 win-unpacked 目录。

## 版本

当前软件版本为 **V0.1.1.3**，工具栏显示完整版本号，`version.json` 为版本来源。此后每次交付小改动默认递增第四位；同一次修改的重复构建不递增。`node scripts/bump-version.mjs` 同步更新版本及打包配置。

## 操作日志

每次启动生成一个独立日志，保存在项目根目录 `logs/`，正常关闭时追加 `session.end`。文件名包含版本、北京时间、进程号及唯一后缀，例如 `MultiViewBrowser_V0.1.1.0_2026-11-02-18-30-00_123_456_ab12cd34.log`。文件采用逐行 JSON，包含时间、启动后毫秒数、操作顺序、操作类型以及必要的窗口编号和音量数值；编号 `slot:0` 表示主窗口，`slot:1` 表示2号窗口。

记录界面点击、双击、输入操作类别、键盘操作类别、拖拽、布局/收藏/工作区操作、导航动作、网页点击/滚动、音量及静音变化、窗口状态和退出。连续输入、滚动会适当节流。**不记录具体网址、网页标题、键入的文字、按键字符、收藏名称、密码或 Cookie**，也不记录原始错误内容。日志以固定操作标识和白名单字段写入，便于分享排查问题。

强制结束进程或断电可能没有退出记录，之前已写入的记录仍保留。日志不会自动清理。将免安装目录移出项目后，日志保存在 exe 同级的 `logs/`；目录不可写时回退至 Electron userData 下的 `logs/`。

## 当前交互

- 按钮、图标、标签及浮窗文字不可选中复制；地址栏、表单和备注可正常选择、编辑及复制文字。空窗口标题栏只保留窗口简称，不显示“空槽位”。

- 16 种递归分割布局，可拖动分割线，保存自定义布局。网页可处于任意槽位；关闭后留空，不补位。
- 名称为主窗口、2号窗口、3号窗口等，拖动按钮仅显示主、2、3等简称。
- 拖动标题栏按钮到其他窗口的网页内容、标题栏或空槽交换位置，不重新创建浏览器实例。拖动时网页继续显示，空槽隐藏添加按钮并显示“拖拽至此处交换”。
- 左键链接在当前窗口打开，只有中键填入编号最小的空槽；满槽忽略。非中键脚本弹窗也在当前窗口打开。仅允许 HTTP/HTTPS。
- 双击主窗口外围留白放大，再次双击恢复；双击其他窗口外围留白与主窗口交换。网页内容本身不拦截双击。
- 放大时隐藏其他网页，仅非主窗口临时静音；主窗口保留用户音量/静音状态。放大主窗口期间临时采用2K（2560×1440）逻辑视口并自动适配，恢复分屏后还原原有分辨率和缩放模式。恢复后恢复其他窗口的配置。
- 网页缩放的逻辑分辨率可下拉选择1920×1080、2560×1440、3840×2160，新增网页默认1080p；旧版自定义分辨率保留至选择新预设。
- 悬停网页缩放按钮显示约300×240 DIP的原生小浮窗，网页继续显示且尺寸不变；修改立即生效。鼠标可从按钮移入浮窗操作，移出两者后自动隐藏，拖拽和窗口移动/缩放时也会隐藏。
- 总音量默认100%，范围0–150%，四个刻度25/50/75/100附近吸附，方向键按5%调整。点击总扬声器静音，再次点击恢复保留值。
- 悬停子窗口扬声器显示等宽、居中的原生浮层，网页尺寸不变；点击仍切换静音。页面独立音量可选0/25/50/75/100%，与总音量分别保存，实际输出按乘积计算。
- 网页被换入主窗口时清除此前静音选择；页面音量为0时恢复100%。全局静音仍优先。
- 收藏名称、网址、分组、备注在一张表单保存。分组和收藏可拖动排序，也可跨组移动收藏。可开关横向收藏栏，隐藏组名，组间使用 | 分隔。
- 可保存/应用/重命名/删除自定义布局和工作区，默认恢复上次会话；JSON 导入导出包含完整配置，导入会替换现有数据。

## 缩放和音量限制

contain 模式为实验性，固定逻辑视口默认1920×1080，使用 Chromium 设备模拟等比缩放并居中。在150% DPI下的历史合成鼠标坐标测试未全部通过；可选择原生响应式兼容模式，恢复常规 Chromium 视口。响应式模式可能没有外围留白。

可安全接入 Web Audio 的媒体支持最高1.5倍增益；跨域无CORS授权、DRM、已有音频图及网站自有Web Audio引擎可能无法增强或调整。总静音和页面原生静音不依赖增益机制。Bilibili账号、聊天、直播长时间运行、IME和多屏DPI仍需现场回归。

## 数据与安全

数据位于 Electron userData/config.json，通常为 %APPDATA%/multiview-browser。配置版本为1，采用schema校验、临时文件替换和有效备份；主文件损坏时读取.bak。共享persist:multiview Session，不额外存储密码或导出Cookie。

远程网页关闭Node集成、启用沙箱与上下文隔离；受限preload仅处理媒体和可信鼠标/拖放事件。IPC校验来源与数据。摄像头、麦克风、通知默认拒绝。仅由应用工具栏发起的有效拖动会话可以交换网页。
