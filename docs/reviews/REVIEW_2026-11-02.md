# 现有功能代码审计（2026-11-02）

本轮只审计，不修改产品代码、不重新打包。新增可重复运行的审计脚本与结果；全部使用临时配置和本地测试页面，没有操作用户真实登录会话。

## 优先修复

### 1. [P1] 旧配置整份回写会覆盖新状态（已运行验证）

位置：[App.tsx](../../src/App.tsx)、[main.ts](../../electron/main.ts)。

渲染进程延迟180ms保存整个Config；主进程的音量、拖拽和新窗口处理同时从磁盘读取、修改并保存Config。没有修订号、旧写拒绝或字段级合并。主进程向UI只广播session，不能保证其他配置字段与所有已发出的保存请求一致。

实际IPC验证：保留100%的旧快照 → 原生音量浮层调25%，存储为25% → 提交旧快照后存储恢复100%。这验证了旧写覆盖的能力；自动操作发生概率还取决于消息和渲染时序，不将手工排序的复现误称为已复现每一种自然竞态。

影响不限音量，还可能撤销刚完成的换位、重新带回已关闭页面或丢失新增网页。建议由主进程维护单一内存状态，UI提交带版本号的动作/补丁，持久化只负责落盘。

证据：review-runtime-results.json 的 staleSave：100 → 25 → 100。

### 2. [P1] 主媒体选择不会从仍在DOM中的旧播放器移交（已运行验证）

位置：[media-preload.ts](../../electron/media-preload.ts)。

volumeSource只在原元素断开连接，或新媒体面积严格更大时切换，没有考虑旧播放器已暂停、结束、隐藏或被替代。网站保留旧播放器节点、同尺寸重建新播放器时，新媒体无法成为同步来源。

模拟实际preload运行：旧播放器暂停但连接保留，新播放器同面积且正在播放；应用下发25%后，旧播放器volume=.25，新播放器仍为.75；新播放器随后调50%也没有site-volume上报。这能再次造成“应用音量与内置音量独立”。

建议明确媒体生命周期和用户交互优先级，交接给当前活动播放器；不要单靠面积单向递增选择。首次加载就暂停的播放器也应单独检查，因为当前来源判定要求!paused。

证据：review-media-results.json，defectReproduced=true。

### 3. [P2] 网页程序化音量变化会清除手动静音/默认静音（已运行验证）

位置：[main.ts](../../electron/main.ts)、[BrowserManager.ts](../../electron/BrowserManager.ts)。

网页site-volume事件与用户操作软件音量浮层共用updatePageVolume；该函数只要value>0就设置audio="unmuted"，无法区分网页程序化更新与用户明确解除静音。

实际验证：第2个窗口手动静音，nativeBefore=true；网页脚本把video.volume改为.75后，audioAfter="unmuted"、nativeAfter=false。默认应静音的副窗口也可能被打开声音。

建议分离“同步百分比”和“用户解除静音”动作；前者保留audio策略，后者才允许更改它。

### 4. [P2] 原生网页获得焦点不会更新外层选中槽位（已运行验证）

位置：[App.tsx](../../src/App.tsx)、[BrowserManager.ts](../../electron/BrowserManager.ts)。

选中槽位只在React section的pointerdown中更新；WebContentsView不是该DOM的子节点，网页上的点击不冒泡到section。BrowserManager也没有把网页focus传给UI。

实际验证：第2个网页获得焦点，secondFocused=true，但rootSelectedBefore和rootSelectedAfter始终为0。随后单击收藏/收藏当前网页等依赖selected的操作可能作用于错误的窗口。

建议把原生网页focus对应的稳定page ID通知UI，再按当前槽位映射更新selected。

## 静态确认的其他问题

### 5. [P2] 收藏不能拖入已有网页的内容区域

位置：[FavoritesList.tsx](../../src/components/FavoritesList.tsx)、[App.tsx](../../src/App.tsx)、[drag-preload.ts](../../electron/drag-preload.ts)。

收藏拖动仅设置favorite数据并更新React drag状态，不启用原生覆盖层。接收favorite的代码仅在React section的onDrop中；现在网页preload已移除拖放监听，而原生覆盖层只接收application/x-mvb-slot。因此拖到标题栏/空槽与拖到已加载网页内容区域行为不一致。建议收藏拖入网页也走原生目标识别，动作明确为打开收藏，而不是交换窗口。

### 6. [P2] 退出时没有可靠的最终保存握手

位置：[App.tsx](../../src/App.tsx)、[main.ts](../../electron/main.ts)。

正常保存有180ms延迟，beforeunload只是发起异步IPC，没有等待主进程确认；关闭流程也没有阻止销毁直到最新状态提交成功。因此最后一步设置、地址编辑或排列在快速关闭时存在丢失风险。此项为静态可靠性缺陷，本轮未声称已稳定复现用户数据丢失。建议主进程拥有实时状态并在关闭时同步落盘，或实现有超时与确认的关闭握手。

### 7. [P2] 低位窗口的音量浮层可能超出屏幕可操作范围

位置：[VolumePopup.ts](../../electron/VolumePopup.ts)。

浮层固定出现在按钮下方，高160px，没有检测显示器workArea、翻转向上或边界夹取。把底部子窗口压得较矮时，按钮下方空间可能不足160px，最底部音量档不可见。建议优先下方，空间不足时向上展开，并按当前显示器工作区约束。

### 8. [P2] 导入收藏允许悬空分组，数据会被界面隐藏

位置：[model.ts](../../src/core/model.ts)、[FavoritesList.tsx](../../src/components/FavoritesList.tsx)。

schema分别校验groups和favorites，但不验证favorite.group存在于groups。UI只遍历groups后筛选收藏，缺少对应分组的收藏因此不会显示；导入重复组名和重复收藏ID也缺少完整性校验。建议导入时补齐/归一化分组、校验ID唯一性，或拒绝不一致数据。此项来自静态代码路径，尚未做实际导入对话框操作验证。

## 已知限制，不作为新增缺陷重复计数

- 固定视口contain模式的不同DPI坐标兼容性仍未完整验收。
- 跨域iframe、DRM、网站自有音频图不保证可统一增强；不能把同源iframe通过等同于所有网站通过。
- 嵌套分割的最小尺寸按局部分支约束，不能保证每个叶子都达到120px。
- 真实站点验证码后的直播播放和系统鼠标OLE路径仍需要人工验收；现有脚本的可信CDP拖放不等于全部桌面路径验收。
