# Windows 11任务栏预览与浮窗（2026-11-14）

## 现象与证据

用户报告V0.2.1.7任务栏图标、缩略图或Aero Peek预览时出现页面暂存、不同槽位的网页缩放面板。本次基于当前V0.2.1.8修复，交付V0.2.1.9。

本地隔离配置使用三个静音测试页和一个暂存页，临时记录DOM事件类型/可信标志、控件所属槽位、请求目标、客户区/屏幕坐标、当前原生鼠标位置及窗口show/hide/focus/blur。原始JSON仅保存在忽略的诊断文件中，不写入正式操作日志，不提交网址、标题或用户会话。

旧诊断窗口的用户反馈为“缩放还有，暂存没了”。记录中缩放在约90.8秒由正常按钮事件显示，此后预览阶段没有新的scale-show请求。浮窗使用showInactive，不一定获得焦点；此前代码只监听浮窗自身blur与主窗口move/resize/minimize/hide，主窗口失活不会主动隐藏未获焦点的浮窗。因此“预览时出现”不能直接等同于“预览伪造点击或随机新开”，已显示的自有窗口也会残留并参与窗口预览。

另以状态回归测试确认独立缺口：即使实际鼠标远离按钮、应用不活跃，或首次异步加载期间状态失效，旧显示路径仍接受请求。初始14项测试中9项失败。暂存原路径甚至未检查主窗口可见/最小化状态。

近期主题提交只改颜色与样式安装；全窗口设置没有新增这两个打开入口。缩放入口在初始导入历史已存在，暂存悬停入口在e4bae66已存在。现有证据不支持把问题认定为V0.2.1.7新引入的鼠标坐标偏移。两个类各自保存状态，没有共用目标ID或重复绑定打开监听；缩放目标来自实际按钮绑定的页面ID，而非当前selected/focus。不同编号与此前操作过的按钮相关，不需要改动焦点或交换逻辑。

## 最小修复

- HoverPopup.ts集中校验：主窗口可见、非最小化；焦点属于主窗口或其自有浮窗；screen.getCursorScreenPoint实际落在按钮锚点内。主窗口getContentBounds、IPC锚点和cursor均为Electron DIP；preload已转换UI比例，此处不再乘Windows DPI。
- ScalePopup.ts与PageStash.ts在创建前及await加载完成后复查条件；原generation继续取消已失效请求。
- 主窗口或浮窗失去整个窗口族的激活时立即hide并使挂起显示失效；焦点进入本应用浮窗时保留。没有增加固定延时、轮询或定时关闭；原鼠标跨入浮窗的180ms宽限不变。
- App.tsx复用相同按钮处理函数供悬停与点击使用，确保后台首次进入被拒绝后，用户实际点击仍可正常打开。目标仍绑定该槽位的网页实例。
- 没有修改网页实例、音频、窗口布局、交换或焦点归属算法。

## 验证与边界

- 87项单测通过，含18项新的浮窗状态/生命周期用例：独立鼠标位置、后台、隐藏、最小化、异步加载失效、自有浮窗焦点及立即关闭/不自行重开；旧异步取消测试补齐原生焦点模拟。
- popup-hover-smoke在真实Electron窗口中验证空/非空暂存区、90%/100%/125% UI比例、三个页面槽位。窗口族焦点为实际Electron焦点；DOM事件与鼠标坐标为明确建模的测试输入，不冒充实际Windows任务栏操作。
- 窗口尺寸覆盖1000×700、1600×900、2200×1200，渲染器模拟DPI1/1.5/2；空/非空两轮共30组通过。原生显示环境为Windows 11、150% DPI；模拟不等于所有真实混合DPI多显示器环境。
- 用户在标题含FIXED的隔离窗口完成任务栏图标/缩略图、Aero Peek、应用切换及浮窗下拉操作对照，反馈“均无异常”。不据此宣称覆盖全部Windows壳版本或所有预览缓存状态。
- 页面暂存专项与12种主题/强调色组合、独立进程偏好恢复、设置和六种窗口交换焦点回归通过。测试页全程静音，实例保留。
- 此前纯DOM测试不移动系统鼠标；正常打开路径现用明确的测试专用指针模型，实际输入保护的反例由专项验证，测试替身不进入生产包。

临时诊断只用于本轮排查；正式操作日志继续遵守既有隐私白名单。原始本地日志不可视为适合公开的用户数据收集功能。
