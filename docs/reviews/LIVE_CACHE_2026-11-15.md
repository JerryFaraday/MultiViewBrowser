# 直播房号缓存与检测优化验证

日期：2026-11-15；交付版本：V0.2.2.1。优化现有检测，不增加设置项或改变收藏点击/拖动规则。

## 存储与校验

位置为原有配置的`favorites[].liveCache`，普通网页为`null`。无独立UID文件。字段：

| 字段 | 含义 |
| --- | --- |
| `formatVersion` | 缓存格式，当前为1 |
| `inputRoomId` | 用户输入的规范化房号，十进制字符串 |
| `realRoomId` | API确认的真实房号，十进制字符串 |
| `uid` | API确认的主播UID，十进制字符串 |
| `checkedAt` | 最近成功解析/到期校验的Unix毫秒时间 |

缺失、损坏或不认识的缓存格式只清为无缓存，不使旧收藏加载失败；类别/房号改变后清除旧映射。同房号复制可保留，删除收藏自然删除缓存。缓存无强制失效；到24小时才需要推进校验时间，未来异常时间戳也安排重新校验。

## 主备接口与异步安全

真实GET验证`/room/v2/Room/get_by_ids?ids%5B%5D=...`，成功`code=0`，`data`以真实房号为键，字段`roomid`、`uid`、`short_id`、`live_status`。必须核对键与真实房号、输入与真实/短号关系，歧义或缺失成员转备用；不因存在缓存改用UID主查。每批最多50个房号。

备用沿用`room_init`与`get_status_info_by_uids`。已有缓存直接查UID，未缓存才解析。过期缓存可先返回状态再独立验证；可靠批量身份数据足以确认时不额外解析。前台/后台各一个串行队列、各起始间隔至少1秒；超时、输出限制及AbortController继续由原生请求包装执行。网络/限流/HTTP/临时接口错误不删除缓存；身份不匹配或明确房间错误安排验证，只有可靠成功结果覆盖缓存。重复输入房号共享任务与状态，所有对应收藏同步更新。

只对首次补齐、身份变化或到期成功校验排队写入。500ms合并多个收藏补丁，保存前读取最新配置并核对ID、类别、房号，只改缓存字段，沿用ConfigStore原子文件替换。不会因每次live_status变化写盘。原有三方合并保留尚未提交的收藏编辑。写失败保留补丁供后续机会重试，退出冲刷待写数据；磁盘持续不可写仍可能无法持久化，日志仅记录允许的失败标识。
