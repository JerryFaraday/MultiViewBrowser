# V0.2.6.3：系统Tooltip残留的后续修复

用户在V0.2.6.2再次提供残留截图，证明mouseLeave送达并不等同Windows原生Tooltip已销毁。此前测试只验证mouseout和title保留，验收范围不足。改为由SettingsService在应用自有BrowserWindow文档安装受控DOM提示：title保存为data-hidden-title并移除原属性，阻止系统Tooltip创建；使用现有主题变量、固定窗口内定位、pointer-events:none。保留提示开关、已有aria-label，并为原来依赖title的操作提供辅助名称。第三方WebContentsView不安装此脚本。

400ms只是正常悬停出现的交互延时；失焦/可见性变化/输入/滚动立即隐藏并取消待显示任务，不使用轮询或延迟关闭掩盖残留。窗口内DOM内容不能作为系统置顶提示覆盖其他应用。保留上一版原生hover清理作为辅助，但不依赖它作为提示关闭保证。

本轮隔离测试关闭窗口时还实际触发webContents为null的异常，用户截图来自dist-electron/native-tooltip-smoke.cjs。已修复为保存原WebContents引用并检查销毁状态，新增回归覆盖该关闭阶段；终止的仅为本轮遗留隔离进程。不能将这次异常描述成用户误操作。

验证：296项单测、类型/构建及格式检查。原生窗口测试实际显示受控提示，激活另一个窗口后检查hidden=true，验证title不再存在、提示开关有效、销毁退出无异常。完整设置专项首次出现收藏分组保存检查失败，保留该结果并复跑核查，不将该次失败隐去。实际Windows Alt+Tab及所有DPI仍需用户复核，不宣称所有环境穷尽验收。视觉变量沿用现有体系，网页布局、音量和交换规则不修改。


完整设置专项诊断显示失败时编辑器已正常关闭，固定350ms读配置早于异步保存完成。测试改为最多1.5秒等待收藏/分组的实际配置结果后全部通过，未改变产品保存时序。原始失败仍记录于此；修复后的提示显示/隐藏/开关及销毁专项通过。
