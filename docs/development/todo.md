## TODO-001：macOS ARM64 版本适配

**状态：待规划**

**目标：** 在保留 Windows 版本完整功能的基础上，增加适用于 Apple Silicon（M 系列芯片）的 macOS ARM64 版本，保证两平台主要功能及交互逻辑一致。

**主要需求：**

- 复用现有 Electron / Chromium、React、TypeScript 和业务逻辑；梳理平台差异，避免维护两套独立业务实现。
- 解决 Windows 专用 C++ / WinHTTP 直播检测程序的跨平台兼容问题；评估平台适配层或替代实现，保留现有平台支持、检测状态、轮询与缓存语义。
- 适配 macOS 窗口管理、焦点、拖拽、弹窗、全屏及快捷键，梳理 Command / Control 差异及系统惯例，检查原生窗口与网页视图的生命周期。
- 增加 macOS ARM64 构建、打包和测试流程，梳理原生依赖、资源路径、文件名大小写及分发要求。
- 建立 Windows 回归与 macOS 验收范围，覆盖分屏、标签页、暂存、收藏、工作区、音频、网页缩放、设置、数据导入导出及直播检测；保留现有配置和数据兼容性。

**待确定事项：**

- 最低 macOS 版本、Electron 与原生依赖支持范围及真实 Apple Silicon 测试设备。
- 直播检测的跨平台技术路线、构建依赖、网络行为及故障处理方案，尚未选定实现。
- 窗口、全屏、焦点、拖拽和快捷键的平台差异处理边界；必要例外如何说明及验收。
- 构建环境、自动化测试、安装包形式、签名、公证及更新分发方案。

**验收方向：**

- 在约定的 Apple Silicon / macOS 环境中完成构建、安装、启动及主要功能验证。
- Windows 完整功能保持可用；两平台主要交互一致，必要平台差异有明确说明。
- 配置、收藏和工作区无非预期丢失或破坏；直播检测、生命周期及平台专属交互有回归证据。

## TODO-002：广告屏蔽功能

**状态：待规划**

**目标：** 为浏览器增加网页广告屏蔽能力。

**主要需求：**

- 研究 Electron / Chromium 下第三方广告屏蔽插件、规则引擎及自研模块的可行性，不预先指定插件、模块或实现方式。
- 优先评估兼容性、性能开销、规则更新机制及长期维护成本。
- 支持在软件设置中启用或关闭广告屏蔽，明确开关的生效范围及时间。
- 评估按网站设置例外规则的必要性及用户恢复网站正常功能的途径。
- 不影响正常网页加载、视频播放和直播间功能，并覆盖现有多个网页会话与窗口场景。

**待确定事项：**

- 技术路线、规则来源、授权许可、更新与失败回退机制。
- 网络请求拦截与页面元素隐藏的需求边界、性能预算及兼容性测试样本。
- 默认状态、是否需要重新加载页面、网站例外的匹配方式及持久化范围。

**验收方向：**

- 约定的广告样本可被屏蔽；开关行为明确且可验证，网站例外如纳入范围则按约定生效。
- 普通网页、视频和直播间的正常功能保持可用，出现兼容问题时可通过明确方式恢复。
- 有性能对比、规则更新与失败场景验证；结果满足正式开发前确定的标准。

## TODO-003：浏览历史记录

**状态：待规划**

**目标：** 增加类似常规浏览器的历史记录功能。

**主要需求：**

- 自动记录网页访问历史，至少包括访问时间、网页标题及 URL。
- 提供历史记录查看、搜索和删除功能。
- 支持在设置中启用或关闭历史记录；关闭后不再新增历史，已有历史是否保留须在实施前形成明确规则并向用户说明。
- 研究持久化方式、容量限制及自动清理策略。
- 与现有标签页、收藏夹及工作区兼容，明确重定向、重复访问、恢复页面等场景的记录时机。
- 明确数据职责：历史记录是访问轨迹；页面会话恢复用于恢复运行状态；暂存用于保留页面实例；收藏用于用户主动保存。不得以历史记录替代这些功能，也不得混入操作日志。

**待确定事项：**

- 记录触发点、时间表示、标题更新、去重规则和恢复会话是否计为新访问。
- 存储格式、容量与保留期限、自动清理、删除范围及是否纳入导入导出。
- 默认开关状态、关闭后已有历史的保留或清理规则，以及重新开启后的行为。
- 搜索范围、查看入口、删除交互及敏感浏览数据的访问与保护边界。

**验收方向：**

- 按约定准确记录时间、标题和 URL，重启后可按持久化策略查看、搜索与删除。
- 关闭记录后不再新增历史；已有数据处理、重新开启及自动清理均符合明示规则。
- 删除历史不误删收藏、工作区或会话数据；现有恢复、暂存及收藏逻辑保持可用。
- 容量、性能及隐私边界有测试，历史内容不进入现有操作日志。

## TODO-004：调试模式

**状态：待规划**

**目标：** 允许用户直接在软件中开启或关闭开发调试能力。

**主要需求：**

- 在设置界面增加调试功能入口及开关。
- 评估是否支持直接开启当前网页的 Chromium DevTools。
- 评估主进程、渲染进程及网页调试信息的查看方式，明确各入口的作用范围。
- 与现有操作日志、详细诊断模式及日志保留机制合理整合；严格区分调试工具与日志记录等级，避免重复设置。
- 调试功能不得破坏现有安全隔离、数据持久化及浏览器正常运行。
- 调试输出不得未经明确授权持久化敏感浏览数据；保留现有操作日志的允许列表和敏感数据限制，不能因开启调试而绕过。

**待确定事项：**

- 功能边界与交互方案，包括默认状态、启停生效时机、是否记住开关、关闭后已开启工具的处理方式。
- DevTools 是否纳入范围、目标网页选择、主进程与渲染进程调试方式，以及可用环境。
- 与详细诊断模式及日志等级的职责划分，查看、导出、保留与清理的规则。
- 如确需持久化敏感调试数据，明确授权的范围、提示、存储期限及删除方式；本条规划不构成该授权。

**验收方向：**

- 调试开关及所选工具按正式确认的边界工作，调试目标清晰，关闭后的行为可验证。
- 现有日志等级和保留机制不出现重复或冲突，操作日志继续满足敏感数据限制。
- 未经明确授权不持久化敏感浏览数据；安全隔离、配置持久化和正常浏览不受破坏。
